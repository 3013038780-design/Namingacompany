## 一 不得更改的执行规则

1. **四个角色对应四个不同 Agent 实例**，在 `run.json` 记录实际 Agent ID 和执行回执引用。主控独立于四个角色。可以按资源限制顺序启动，不要求同时运行；禁止一个 Agent 冒充两个角色。
2. **固定顺序**：Agent 1 → Agent 2 → 主控中文质量评审 → Agent 3 中文筛查 → Agent 4 英文匹配 → Agent 3 英文复查 → 主控终审与交付。Agent 3 的两次审核由同一审查角色负责。
3. 未通过上游验收，不进入下游。返工必须沿原责任链返回并留痕；不得由主控暗中补写后当作角色已执行。
4. 中文全被淘汰时，Agent 4 仍须实际启动、检查上游结果，提交“输入为零”的回执。英文复查同样提交零输入回执。不得为了走完流程制造弱名字。
5. 缺角色、缺交接或缺证据的轮次只能标“未完成”。全部角色实际执行但没有合格名字，可标“完整执行但零通过”；这是失败结果，不能包装成推荐。
6. **同一家族只计一个独立创意**。同一词根换字、同一意象近义改写、同一中文更换英文都不重复计数。有疑问先合并，写明家族关系。历史提案即使重配英文也不算新增。
7. 不限定“叠”或其他字根。古文素材卡占比不超过 15%；不能让古文、单一技术词根或某一种自然意象占据整个候选池。
8. 用户明确否决优先于分数。未完成注册查询不得写“可注册”“全球未注册”；未见同名不等于名字好。
9. 修改门槛或流程必须先提出变更并获得用户明确同意，再更新本 README 和版本。不能在某轮失败后回头降低标准。

## 二 每批研究规模与四角色交付

默认每批研究目标为 **24 个独立创意家族**，允许产生更多字面版本，但变体单列。素材或质量不足就报告缺额；这些研究数量不是最终名字的合格数量。

| 角色 | 定量要求 | 必交文件与字段 | 交接验收 |
| --- | --- | --- | --- |
| Agent 1 案例研究 | 首个规范轮次至少12个案例，广义科技、本轮AI、RSI相关各至少4个；后续每轮新增或重新实质核验至少6个，各类至少2个。提炼至少6条原则及3个反例 | `cases.json`：案例ID、类别、名字、实际词义、词源事实、研究者解读、已打开的来源、阅读范围、可迁移原则。每条原则包含正例、失败反例和适用边界 | 主控核对数量与三类覆盖；6条原则和3个反例齐全；每个关键词源有正文证据，不能只靠官网品牌存在证明命名动机 |
| Agent 2 素材与中文创作 | 至少24张不同素材家族卡，至少6类来源，任何一类不超过30%；至少阅读2种书籍的具体章节/节选正文，以及3篇近90天新闻正文。古文卡占比≤15% | `materials.json`：素材ID、家族、类别、原文事实、实际阅读位置/范围、来源与日期、可迁移关系。`candidates.json`：候选ID、家族ID、中文、拼音、素材ID、原则ID、释义、组合关系、多层寓意、短板、历史去重结果和自评 | 不声称通读未读整书；一个家族不能拆成多份补数量。先提交中文评分，主控独立复评；所有字面草案都要记录去留 |
| Agent 3 中文与英文审核 | 每个进入筛查的中文至少5组有效查询；每个拟采用英文至少5组。每轮至少2个已知占用阳性对照，含公司和产品各1个 | `screening.json`：查询词、日期、返回摘要、打开的证据、具体使用主体/产品、同名性质、地区与查询范围、登记状态、结论。中文与英文分开记录 | 完全同名的现有科技/AI公司、模型或软件产品直接否决；近似、拼音、跨行业与证据不充分分别处理，不笼统称已注册 |
| Agent 4 英文匹配 | 每个合格中文首轮给1–2案；每案有明确建议读音及构词说明；最多2次返工，每次仍最多2案 | `english.json`：中文ID、英文、音节/读音、词典词或造词、真实构词过程、双语关系、来源/创作说明、负面联想、短板、自评与版本 | 英文须独立成立；不强行逐字翻译。质量通过后交Agent 3复查，不能继承中文的通过状态；仍不合格则只留中文历史储备 |

案例和素材是不同交付：Agent 1 研究别人为什么这样命名，Agent 2 根据原则寻找新材料并创造名字。二者不得合并。新闻不足、书籍正文不可访问或来源类别不足时，记录缺额并继续补搜；不得拿书目介绍、搜索摘要或网页标题冒充正文阅读。

主控对所有进入最终候选的来源逐项复核，对其他来源卡抽查至少20%（向上取整）。发现事实错配、伪造原句或阅读范围夸大，该卡及全部下游名字暂停，交回原角色修正并扩大复核到该角色本批全部素材。

## 二之一 Agent 1 → Agent 2 的强制研究衔接（1.1新增）

每一步必须能说明如何服务下一步：**具体案例发现 → 可迁移命名机制 → 搜索问题与资料选择 → 素材独特关系 → 中文创作 → 质量取舍**。阅读报告、填写分类或原则编号，不等于实质完成交接。主控负责逐环验收，不能仅以数量、字段、哈希和评分放行。

### H1内增加搜索计划验收

Agent 2先提交`search-plan.json`及可读的`search-plan.md`，主控写`plan-review.json`。这是H1内的前置检查，不替代H1–H7，不增加虚构角色。计划未通过不得开始本轮素材批量采集或创作；允许为确认入口做少量可访问性检查，必须标明范围。用户若只授权计划，本轮到计划交付即停，主控验收不自动授权下一阶段。

计划覆盖Agent 1六个主要来源方向；来源未确认的专名单列处理策略，不编词源。科学/计算及自然可再细分，但不能代替其他方向；分类不规定素材必须强行平均。因不适用或资料不足暂不执行的方向，单列理由交主控审阅，不静默删除。用户对一个局部的举例或否定，只修正对应部分，除非用户明确要求，不自动收窄整个方向地图。

每个方向必填以下内容，缺项退回：

| 字段 | 实质验收要求 |
| --- | --- |
| 分类与案例 | 对应A1分类ID；至少2个具体案例ID及名字，并指出报告中的分析位置。不能只写原则编号。 |
| 案例发现 | 分别说明案例借用了什么意义、连接什么世界、建立什么公司身份；区分已证实词源与研究者解读。 |
| 可迁移机制 | 明确学什么、不照搬什么，以及正例和失败边界。不得把所有方向统一为成长、探索或未知。 |
| 阅读与搜索问题 | 至少2个具体问题；写清准备找哪种对象、关系或机制，为什么该案例使这个问题值得找。 |
| 检索路径 | 至少1组中文和1组英文查询；列拟读书籍/章节或新闻/论文/机构资料入口及选择理由。计划入口标`planned_not_read`；已打开的单独标阅读范围，不把书目当正文。 |
| 材料取舍 | 明确保留特征、淘汰条件、历史家族重复风险，以及可能带来的品牌身份和误读。没有命名潜力的真知识也可淘汰。 |
| 下一步产物 | 说明将提交什么素材卡、它将帮助下一步判断什么；本阶段不得夹带新名字。 |

同一机制跨方向可共享，但必须解释差异；按案例逐条列来源不等于学习了机制。主控必须检查推理链，不得暗中重写Agent 2计划后声称原交付通过。计划需返工则保留原版、具体问题及真实Agent 2修订。

### 素材与命名分开验收，小批先行

搜索计划经主控验收且下一阶段获授权后，先提交**6–8张不同家族素材卡**进行小批审阅。每张除既有字段外，增加`plan_direction_id`、`case_ids`、`mechanism_to_material`、`distinctive_relation`、`naming_potential`和`discard_conditions`，说明“为什么沿这条案例结论找到它、什么特征值得保留”。主控逐卡检查后再扩批；若发现共同偏差，先退回，不能等24案结束再评分。6–8是阶段检查点，不替代整批24独立家族目标、来源分布、书籍与新闻阅读要求。

素材通过，只表示值得继续研究，不要求一张卡对应一个名字。好素材可暂不起名，弱素材可停止；不得为每张卡硬配普通中文词。后续生成草案时新增`material_feature_retained`、`material_feature_lost`、`why_name_not_generic`，指出名称保留和损失了哪些独特关系。若从闭包等具体机制退化成无法辨别来源的泛化称呼，应退回审查；不机械要求照抄术语，变形、组合和造词仍可用，但须保留可讲清的意义并自然成立。

主控在H2验收时，同时核对计划与素材、素材与名字的实质联系。所有条目使用同一组原则、复制通用应用话术，不能当作关系已成立的证据。不得以出处真实补偿品牌薄弱，也不得以自行打分推翻用户明确否决。

1.1仅强化前置计划、过程检查和研究谱系；原质量分数、24独立家族整批目标、查重门槛及返工上限均不降低。历史1.0记录保留原版本，不补造计划或验收。

## 三 品牌质量评分与一票否决

分数是**编辑判断**，不是消费者测试或科学测量。每维1–5分：1明显不成立，2问题严重，3勉强可用，4自然清楚，5突出且有辨识。每维必须附具体理由及一个可能的反面联想，禁止只填总分。

### 中文质量门槛

Agent 2 自评，主控不查看其分数先独立复评，再对照。以下门槛两份评审都必须满足：

| 维度 | 最低分 | 判断问题 |
| --- | --- | --- |
| 自然称呼 | 4/5 | 不读释义，能否像一个现成品牌那样顺口称呼？是否像口号、残句或硬改术语？ |
| 记忆与辨识 | 4/5 | 是否有明确声音或画面？是否只是泛化科技词或难以区分的近义组合？ |
| 科技公司/AI Lab身份 | 4/5 | 第一行业联想是否能承载计算、探索、认知、科学或工程？是否更像环保家具、木业、水务、育儿、养生？ |
| 来源与组合关系 | 4/5 | 来源是否真实？组合是否共享动作、结构、因果或角色，而非两字各有好寓意？ |
| 长期延展 | 3/5 | 是否能容纳多年研究及多个产品，而非仅描述一个功能？ |
| 多层含义一致性 | 3/5 | 第二层含义是否自然增厚同一核心，还是互不相关的故事堆砌？ |

**总分至少25/30，且每维达到门槛**。任何关键维度不够，不能靠其他维度高分补救。两评审任一维相差≥2分，退回一次具体复评；仍不一致则暂停，不进入查重或英文阶段。

### 英文质量门槛

Agent 4 自评、主控独立复评。发音自然、听写/拼写、构词真实性、与中文的关系四维各≥4/5；独立品牌辨识≥3/5；总分≥21/25。每维同样需理由和反面联想。建议读音必须标为建议，不能假装新造词有公认读法。

### 直接否决或暂停

- `USER_REJECTED`：用户明确否决；不能换英文后再次当新增。
- `BRAND_FIT`：首要行业气质不符；有科学出处也不能挽救。
- `UNNATURAL`：拗口、口号、残句、机械拼词；解释前就不成立。
- `SOURCE_INVALID`：伪造词源、错误引用、科学事实不支持该关系；暂停相关家族直到修正。
- `EXACT_TECH_USE`：有明确同名科技/AI公司、模型或软件产品使用证据；直接否决。
- `NEAR_MATCH_HOLD`：近音近形或活跃跨行业品牌可能混淆；暂停并写具体风险，不冒充完全同名。
- `EVIDENCE_HOLD`：只见历史域名、个人用户名、OCR片段或无法读到的登记线索；不以此证明占用或清白。
- `HISTORY_OR_FAMILY_DUPLICATE`：已提案或同家族变体；可存档但不计新增。

## 四 名称筛查的最低证据要求

中文5组查询至少覆盖：精确中文无行业限制、中文+公司/科技、中文+AI/模型/软件、繁体（无差异则记录不适用并补另一组）、拼音或合理近音近形。英文5组至少覆盖：精确词无行业限制、公司/Lab、AI/模型、软件/产品、常见分词或拼写变体。查询日志必须记录实际执行的查询，不能预填为已执行。

先查使用，再查权利；进入最终讨论名单时，尝试大陆公司登记及第9/42类商标入口，并按目标市场尝试可访问的境外登记来源。每个地区、每个入口分别记录 `verified / unavailable / not_checked`。入口能打开不等于已完成逐名查询；无法访问也不能写无注册。

| 证据情况 | 允许结论 | 禁止结论 |
| --- | --- | --- |
| 官网或开发者发布页明确使用同名 | 具体主体已使用，按规则否决 | 未查商标却称商标已注册 |
| 第三方企业资料 | 名称/行业/状态线索，注明来源层级 | 假称官方实时登记核验 |
| 只有搜索摘要且正文不可读 | 待核实，可用于继续查找 | 最终肯定占用或无占用 |
| 全部最低查询完成，未见明确同名 | 本轮公开使用初筛未见明确同名 | 全球未注册、一定能注册 |
| 拼音相同、近似游戏名、注销/撤销记录 | 分别写混淆或历史使用风险 | 全当完全同名在营公司，或自动当作可用 |

阳性对照不能替代逐名查询。无命中的候选保留查询日志，不编造“证明无注册”的来源链接。最终候选可标“完整公开使用初筛”，但登记状态仍须逐项披露；未完成官方核验不妨碍如实讨论品牌，不能升级为注册可用结论。

## 五 强制交接与返工记录

每轮 `run.json` 必须声明 `protocol_version: "1.1"`（已归档旧轮次保留原版本）、真实状态、四个角色ID/执行回执、主控ID、研究目标和实际数量。`handoffs.json` 必须有以下7项验收回执；每项包含时间、交付方、验收方、输入/输出文件路径与SHA-256、候选ID、`accepted / returned / zero_input`、验收理由。文件内容变化后相关回执须重新验收。

| 交接ID | 交付 → 验收 | 通过条件与失败去向 |
| --- | --- | --- |
| H1 | Agent 1 → Agent 2 | 案例、原则与反例达到要求，并验收Agent 2搜索计划；案例不足退Agent 1，迁移或计划不足退Agent 2 |
| H2 | Agent 2 → 主控中文评审 | 素材、独立家族、释义、历史去重、自评及计划→素材→名字的实质谱系齐全；失败退Agent 2 |
| H3 | 主控 → Agent 3中文审核 | 双中文评审过线且无一票否决；零通过也提交回执 |
| H4 | Agent 3中文审核 → Agent 4 | 中文公开初筛通过，风险与登记状态披露；占用退Agent 2，未核实暂停 |
| H5 | Agent 4 → Agent 3英文复查 | 英文双评审过线，真实构词与中文关系齐全；失败退Agent 4 |
| H6 | Agent 3英文复查 → 主控 | 英文独立筛查完成；英文占用退Agent 4，不必自动淘汰合格中文 |
| H7 | 主控 → 用户交付 | 角色/交接完整、来源复核、家族去重、双语质量及筛查齐全；任何缺项不得列最终候选 |

零输入回执也要由真实角色检查后提交，输入和输出文件仍需存在；写明上游通过数为0及淘汰统计。不得把“尚未开始”记成“零输入已完成”。

单个中文家族最多返工2次，单个中文的英文匹配最多返工2次。超过上限转历史储备或淘汰，不能继续换字补数。原因码为 `SOURCE_INVALID` 的先修正素材再重启审核。每次返工保存版本、原因、责任角色及新旧结果，不能覆盖原记录后声称一次通过。

## 六 持续交付与统一总库

主控最终只交付各门槛全部通过的名字。每项至少包含：中文/拼音、英文/建议读音、真实出处与阅读范围、组合关系、多层寓意、短板、两份质量评审、中文/英文独立筛查、登记状态、家族ID和去留结论。评分是审美理由，不是给用户看的营销背书。

所有未进入备选的中文与英文也逐名列明：名称、阶段、原因码、具体理由；若涉及占用，必须有公司全称/产品名、同名性质、URL、核验日期与访问范围。品牌质量提前淘汰的标“未全面查重”，不能写可用或已注册。

报告开头直接给**本轮名字与结论**，不能让用户自行翻JSON找结果。统计必须分列：案例数、素材家族数、字面草案数、独立创意家族数、中文通过数、双语完整通过数、历史/同家族重复数及缺额。

用户最新授权采用**持续积累**：取消每天20个、到数交付后停止、每天最多三批、固定09:00报告及“未凑满算未达标”的调度规则。保留每研究批24独立家族及原有研究、阅读、评分和查重门槛；该数字是研究覆盖要求，不是必须造出24个好名字。分阶段完成就登记状态，有合格新增就更新总库，不拿草案或未核实项充数。

所有名字使用稳定目录ID与原始候选ID关联，按六个宏观来源世界分类，交叉关系用标签表示，不为填满分类而起名。总库分别展示公开初筛讨论备选、额外储备、待核实与已否决；查重结论附日期和范围，不把历史通过当作永久有效。每天、每轮和英文返工的计数只作溯源，不设产量排名或数量终点。

每次自动唤醒先接续`research/continuation-queue.json`：优先处理已启动的角色工作、待核证据与未完成交接，再探索此前覆盖较少的方向。只允许一个实际命名轮次写入同一工作队列；已有角色运行时接续，不重复派一套四Agent。轮次结束后保存下一步、当前状态、证据位置和阻塞；不能把“已排队”写成“正在后台运行”。

单次工作段在运行限额、工具不可恢复故障或返工上限时保存检查点，由后续唤醒接续；这不是整个命名工程停止。单名字的返工上限、质量标准及登记披露不变。用户要求停止或暂停时才相应停止调度；不擅自生成没有终点的shell循环或承诺电脑关闭后仍能处理本地仓库。

自动任务必须通过应用的调度工具更新；README或队列文件本身不能启动后台执行。当前沿用同一个聊天自动任务，每小时接续。合并PR、部署或改动网站仍需依已有授权范围执行；本次只维护仓库中的总库文件与现有PR，不改旧网站。
